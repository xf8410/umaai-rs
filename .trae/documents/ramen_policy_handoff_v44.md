注意两条容易混淆的线：

- 第三年 **3500**：RMJ 普通成功线；低于 3500 才是真正没过 RMJ。

不要把“第三年低于 5000”统一称为 RMJ 失败。

## 3. 当前正式推荐 preset 的实况

实现位置：

- `crates/umasim/src/trainer/local_ramen_trainer.rs`
- `RecommendedRamenTrainer::new()`

当前代码中已经固化的主要手法：

- 分年技能 PT 权重：`16 / 64 / 64`；
- 长期结构最多牺牲 140 点当前训练评分；
- 启用属性空间预留、动态体力、概率 Hint、连续失败期望；
- 吃面 PT 权重 2.0；
- 当前真实训练盘面与面覆盖的对齐权重 0.10；
- 用吃面前基础失败率作保守风险预算，但规则执行仍使用真实减失败率；
- Cook2 式诀窍边际库存权重 40；
- 关闭随机分身 lookahead；
- 第一年、第二年体力低于 30 才硬休息，第三年取消硬休息门；
- 吃面前先看本回合是否本来就要训练；已经吃面后，只允许从五种训练中选，避免空吃；
- 有马前允许把体力压低，随后由赛后恢复和超级拉面每回合恢复接管；
- 友人出门可替代本来就要休息的回合；
- 五段友人事件按当前体力、干劲、属性、PT 和事件链进度动态估值；
- 旧的持续 deadline urgency 保持关闭；
- 隐藏风味用法采用吃后库存与后续可做面数量的动态判断。

### 重要：正式代码仍是 `1/3/5`

截至本文提交时，`RecommendedRamenTrainer::new()` 中仍写着：

```rust
local.friend_outing_cumulative_caps = [1, 3, 5];
```

v44 已经确认候选 `0/2/5` 更好，但实验结果**尚未晋级到正式 preset**。因此不能对外声称正式策略已经是 `0/2/5`。

## 4. 已确认的关键实验结论

### 4.1 v42：吃面后必须训练

报告：`.trae/exports/strict-post-eat-ablation-v42.md`

300 局严格同种子消融中，保留和移除该保险门完全同轨：

- 均分变化：0；
- PT 变化：0；
- 属性评分变化：0；
- 配对胜/平/负：`0/300/0`。

玩家解释：当前吃面前判断已经能避免大多数空吃，因此保险门没有改变这批局面；保留它可以防止以后策略改动后出现“吃完面去休息、出门或治病”的坏手。

结论：**保留吃面后必须训练。**

### 4.2 v43/v44：友人五次出门的跨年节奏

v43 枚举了全部 21 套单调累计配额 `(Y1, Y2, 5)`。初筛最高为 `0/2/5`，最低为 `5/5/5`。

`0/2/5` 对 `5/5/5` 的 1000 局复赛：

- 均分 `+2431.1`；
- PT `+310.0`；
- 属性评分 `+1729.5`；
- P10 `+2304`；
- 配对胜/平/负 `733/66/201`。

v44 再用 1000 个相同 seed 直接比较当前 `1/3/5` 与候选 `0/2/5`：

| 指标 | `1/3/5` | `0/2/5` | 候选变化 |
|---|---:|---:|---:|
| 平均总评分 | 57824.7 | 58354.0 | +529.3 |
| 平均 PT | 7651.9 | 7718.1 | +66.2 |
| 平均属性评分 | 39465.8 | 39849.4 | +383.7 |
| 平均五维和 | 9364.8 | 9432.3 | +67.6 |
| P10 | 53826 | 54544 | +718 |
| P50 | 57871 | 58403 | +532 |
| P90 | 61657 | 62426 | +769 |

候选配对胜/平/负：`517/65/418`。

玩家解释：**友人应该尽早点出来并解锁，但不等于第一年就要花出门次数。** 当前卡组与策略更适合第一年把回合用于点卡、开彩和踩训练；第二年累计走两次，第三年再把五次出门收完。

结论：`0/2/5` 已达到晋级正式 preset 的数据标准，下一步应做代码同步和回归，而不是重新做同一轮初筛。

### 4.3 v44：低体力时为“确定跨线”放行吃面

报告：`.trae/exports/cap-and-cross-v44.md`

以 `0/2/5` 为共同基线，各方案 300 局：

| 玩家手法 | 实验 token | 相对 control 均分 |
|---|---|---:|
| 只为当前一碗过 RMJ 普通成功线放行 | `crossrmj` | -4.7 |
| 只为当前一碗过第三年 5000 放行 | `crossgreat` | -23.1 |
| 同时允许上述两条线 | `crossrmj-crossgreat` | -16.2 |
| 为抬普通 PT 常驻档放行 | `crossstep` | -1988.1 |
| 全跨线并要求吃后还能做面 | `crossrmj-crossgreat-crossstep-crosskeep` | -277.6 |
| 不加跨线特判 | `control` | 0 |

玩家解释：能过线不等于这回合就该低体力硬吃。还要看当前是不是一盘真正的大训练、吃后是否导致下一回合必休、以及会不会把后续配方打空。尤其为了抬普通 PT 档而绕过恢复判断，会明显亏掉后续训练。

结论：

- **不晋级任何低体力确定跨线特判；**
- `crossstep` 明确淘汰；
- 旧的持续 deadline urgency 继续关闭；
- 保留原有体力判断和吃面后训练保险门。

## 5. v44 修复了什么，但哪些内容只是实验设施

旧 deadline 逻辑方向有误：吃后仍未达标时产生 urgency 并绕过恢复门，而真正当前一碗跨线后 urgency 反而归零。v44 在实验候选层加入了精确检测：

- 当前一碗首次过本年 RMJ 线；
- 第三年当前一碗首次过 5000；
- 当前一碗提高 PT 常驻效果档；
- 吃后至少保留一种当前已选地区可制作面。

这些检测用于矩阵，不代表应该开启。v44 的赢家是 `control`，清理 PR 时不应把失败候选误当正式手法留下或启用。

## 6. 玩家语义仍存在的缺口

上游机制文档已经很完整，真正缺的是“玩家为什么说这手赚或亏”的决策语义。

### P0：直接影响下一轮策略

1. **大盘吃面、小盘省面**：结合彩圈数、支援卡人头、NPC 人头、Hint、主属性和有效训练值判断这碗面值不值。
2. **吃面对盘**：区分正吃、歪吃、空吃，以及强制赛程前被浪费的面效。
3. **吃后体力转移**：不能只看这回合减失败率，要比较“本回合硬踩 + 下一回合被迫休息”的两回合收益。
4. **配方续航**：吃完当前这碗后还能做几种面，是否因诀窍偏科或隐藏风味不足卡配方。
5. **年末保线**：临近 RMJ 时是否保留至少一碗可做面，而不是只看库存总数。
6. **合宿前存体**：进合宿体力、合宿训练次数、是否第一回合被迫休息。
7. **地区面按卡组选**：第三年地区面的友情倍率与覆盖训练要按速耐、速智等卡组方向估值。
8. **早解锁与早出门分离**：点友人、解锁出门、真正消耗五次出门是三个不同目标。

### P1：解释低分局

1. 前期点卡、开彩进度与弱训练换羁绊；
2. 有效 Hint、废 Hint、重复 Hint 与剩余技能池价值；
3. 诀窍库存偏科、关键配方缺口与队列淘汰损失；
4. 属性真实溢出：区分主属性撞墙、副属性和 PT 仍有效的训练；
5. 目标赛、补赛程、自选多跑与未来连战压力；
6. 合宿大盘利用率；
7. 发牌差、操作差和目标取舍分离。

### P2：后续精调

- 设施等级投资；
- 不同卡组的年初三碗模板；
- 五段友人事件的逐段边际价值；
- 冲均分和保 P10 的风险偏好差异；
- 年末最后两三回合的联合规划；
- 超极阶段三次训练的体力与属性上限利用。

## 7. 上游已知机制风险

上游 `.trae/documents/issues.md` 仍记录一个未解决问题：支援卡“不出现”判定错误地受到得意率影响。

正确语义应是：

1. 先独立判断这张卡本回合是否出现；
2. 确认出现后，得意率只改变它更容易去哪一种训练。

当前实现把两步混在一起，高得意率还会降低“不出现”的概率。因此与 PT 常驻得意率、RMJ 成功效果、彩圈覆盖率和地区面卡组匹配有关的绝对收益需要谨慎解释。同规则、同 seed 的 A/B 仍有比较价值，但不应直接等同实服收益。

## 8. PR #15 的合并风险

当前分支保留了完整实验历史，PR 体积很大，包含：

- 大量一次性 GitHub Actions 工作流；
- v8-v44 期间的 Python 补丁脚本；
- 实验矩阵工具和 token；
- 历史报告，包括已淘汰或曾使用错误基线的实验；
- 可能与上游最新 `master` 不一致的格式化或旁支修改。

因此 PR #15 当前适合审阅实验成果，但**不适合不清理就整包合并**。尤其要防止：

- 把 fork 内部 PR 当成上游 PR；
- 把 v44 的失败跨线候选当正式手法；
- 在没有同步代码时声称正式出门节奏已经是 `0/2/5`；
- 保留会自动提交报告的临时 workflow 权限；
- 用 stable `cargo fmt` 重排全仓。项目规定格式化只能由用户手动运行 Nightly rustfmt。
