# 历代 UmaAI 逻辑扫描与拉面杯缺口审计

更新时间：2026-08-23

## 扫描范围

本审计聚焦会实际影响决策质量的主干代码，而非逐行枚举所有资源文件。

- `hzyhhzy/UmaAi`
  - `master`：机甲杯手写逻辑、UCB 搜索
  - `Cook` / `Cook2`：田园杯料理与材料边际价值
  - `UAF` / `highpt1`：周期目标、相谈机会成本、PT 偏好
  - `LArc` / `NNInputV2`：海外适性、SS 蓄积、完整剧本特征
  - `Legend`：多阶段事件、颜色控制、资源满槽与中断成本
- `xulai1001/UmaSimulator`
  - `Legend`：复杂多阶段手写策略与阶段事件决策
- `xulai1001/umaai-rs`
  - 温泉杯手写评估、扁平蒙特卡洛、UCB、CRN、NN leaf、collector
  - 拉面杯 `FlatSearch<RamenGame>` 搜索内核与 RNG 分支支持
- `EtherealAO/UmaAi`
  - 早期神经网络搜索、分布价值、按排名加权的激进度、批量推理结构
- 当前 `xf8410/umaai-rs` 工作分支
  - `RamenPolicy`、`LocalRamenTrainer`、v8 窗口、Cook2 库存成本、矩阵基准

## 历代逻辑中反复验证有效的设计

1. **训练即时收益与长期结构分开估值**：属性/PT、羁绊、Hint、体力、失败率分别计分。
2. **属性上限使用软约束**：不是到上限才截断，而是按剩余回合提前预留终盘固定收益空间。
3. **资源使用按边际价值收费**：田园杯用凹函数评价材料，UAF 按刷新前剩余回合评价相谈。
4. **周期目标具有 deadline urgency**：越接近大会/RMJ/刷新点，未达标资源的影子价格越高。
5. **复合动作绑定评价**：料理+训练、相谈+训练、Overdrive+训练必须作为组合比较。
6. **失败按期望分布评价**：区分小失败与大失败尾部，而非单一硬阈值。
7. **搜索使用终局 rollout**：根节点动作后由基策跑到终局，UCB 将更多预算分给有希望的候选。
8. **风险偏好随剩余回合变化**：按终局分布排名加权，而非只比较均值。
9. **公共随机数降低候选差值方差**：相同 rollout 序号共享随机未来。
10. **剧本专属状态必须进入策略/特征**：历史 NN 输入都包含资源、阶段、进度、合法动作和人物状态。

## 当前已经具备的能力

- 拉面杯规则模拟与完整阶段推进。
- 拉面搜索内核 `FlatSearch<RamenGame>`、UCB、终局 rollout、可复现分支 RNG。
- 当前真实训练窗口与拉面覆盖绑定（v8 window）。
- Cook2 式 A/B/C 诀窍边际库存成本。
- 羁绊、Hint、动态体力、属性预留、失败风险等本地手写结构。
- 同 seed 配对矩阵、绝对分数分位数、最高分 seed 报告。

当前 150 seed 单卡组结果：

- `cook2-40` 平均最终评分 `54613.7`
- P90/P95/P99：`58535 / 59105 / 60742`
- 单局最高：`61835`，`run_idx=108`，可复现种子 `61552`

## P0：当前最关键的接线缺口

### 1. 最佳策略没有成为正式默认手写策略

跑分最佳的是 `LocalRamenTrainer` 的 `window10 + rawfail + cook2-40`，但：

- `umasim` 中 `trainer="handwritten"` 的拉面路径仍实例化 `RamenHandwrittenTrainer::new()`；
- `FlatSearch<RamenGame>` rollout 的关联训练员仍是 `RamenHandwrittenTrainer`；
- `LocalRamenTrainer` 主要通过矩阵 token 构造，只在实验 binary 中使用。

后果：报告里的 `54613.7` 不是用户正常启动程序时实际得到的策略，也不是蒙特卡洛 rollout 的基策。

### 2. 拉面 MCTS 搜索内核已存在，但正式训练员入口未接通

`FlatSearch<RamenGame>` 可以搜索，但 `MctsTrainer` 只实现 `Trainer<OnsenGame>`。`umasim` 遇到：

```text
scenario="ramen", trainer="mcts"
```

会明确回退到 `RandomTrainer`。这是目前最大的功能断层。

### 3. 实时 AI 通道仍然只支持温泉杯

`crates/umaai/src/main.rs` 只解析 `GameStatusOnsen`，只提供 `calc_onsen_training/event`。拉面杯没有：

- 协议状态解析入口；
- 拉面阶段推荐输出；
- 吃面/隐藏风味/地区/超级拉面交互；
- 实时 MCTS 或最佳手写策略接线。

## P1：最可能继续提升跑分的策略缺口

### 4. 没有完整的“周期目标 + deadline urgency”模型

历史 UAF 会按距离下一次刷新/大会的回合数提高未达标目标价值；当前拉面只有：

- 可选的跨档一次性/持续奖励；
- RMJ 前库存成本折扣；
- 库存溢出压力。

缺少按“还差多少剧本 PT、预计还能做几碗、剩余多少产出回合”计算的动态紧迫度。应显式估计 RMJ 成功/大成功可达性，而不是只在单次吃面恰好跨线时奖励。

### 5. 年末资源清算和保底储备不完整

田园杯对 URA G1Plate 有明确储备和最后一回合清仓逻辑。拉面当前缺少统一的：

- 年末前剩余诀窍的清仓价值；
- 为下一次可制作拉面保留 A/B/C 配方的最低库存；
- 隐藏风味在当年末与全局终盘的不同影子价格；
- 第三年 5000 PT 大成功可达性保底。

### 6. 隐藏风味方案只按“使用数量最少”选择

`SpecialSelect` 主要最小化隐藏风味总数。同样使用 0/1/2 个隐藏风味的多个方案之间，没有比较：

- 吃后 A/B/C 库存平衡；
- 后续三碗的可制作集合；
- 队列中即将因上限被丢弃的诀窍类型；
- 年度剩余配方需求。

Cook2 库存成本目前用于“选哪碗面”，尚未用于“同一碗面选哪种替代方案”。

### 7. 地区选择仍偏静态

当前地区评分主要看卡组类型偏好、训练/友情/PT/Hint 静态效果。缺少联合评价：

- 三个配方对 A/B/C 产出分布的匹配；
- 年内预期可制作次数；
- RMJ PT 可达概率；
- 各训练覆盖互补性；
- 第三年超级拉面和终盘目标。

历史剧本通常把“选路线/选 Buff”当独立长期规划问题，而不是单纯静态加权。

### 8. 超级拉面选择仍是弱策略

`LocalRamenTrainer` 没有专门处理 `SuperRamenSelect`，多候选时默认索引 0。历史代码会针对长期效果、路线颜色或装备方向专门选择。超级拉面应比较三个训练覆盖组合对当前卡组、属性缺口和终盘剩余回合的价值。

### 9. 复合动作没有在根节点统一搜索

当前拉面搜索按标准阶段依次处理 `RamenSelect -> SpecialSelect -> Train`。搜索内核注释明确不接受 combined ramen action。虽然每阶段都能搜索，但候选预算被拆散，且正式 MCTS 未接入。

理想根动作是：

```text
(不吃/地区, 隐藏风味方案, 预期训练策略)
```

至少应让“选面 + 替代方案”形成组合候选，避免前一阶段不知道后一阶段会选择哪种资源方案。

### 10. 事件选择仍是单步静态估值

拉面事件使用通用属性/PT/体力/干劲/坏状态折算。历史逻辑会对：

- 友人事件链阶段；
- 特定剧本资源；
- 未来固定事件；
- 选项概率与后续状态

做专门处理。拉面事件是否产生诀窍、隐藏风味、地区效果或后续链，目前缺少策略级长期估值和事件搜索。

## P1：搜索与 AI 缺口

### 11. 拉面 MCTS rollout 仍使用旧弱基策

`FlatSearchGame for RamenGame` 当前关联：

```rust
RamenHandwrittenTrainer
```

而不是已验证更强的 `cook2-40`。即使接通 MCTS，弱 rollout 会扩大搜索偏差，并浪费大量样本弥补基策缺陷。

### 12. 尚未实测“拉面 MCTS 相对最佳手写每回合多多少分”

温泉的 `mcts_turn_bonus=70` 是经验校准；拉面不能照搬。需要同 seed 配对：

- `cook2-40` 完整育成；
- 拉面 MCTS 完整育成；
- 多档 `search_n/group_size/radical_factor`；
- 统计最终差值，再按有效决策回合校准显示补正。

### 13. 拉面 CRN 收益测试存在但没有正式结果

代码已有 ignored 的 `test_crn_pairing_gain_ramen`，但报告中没有目标剧本的相关系数、等效样本倍率与建议 `search_n`。温泉的 3.65x 不能直接用于拉面预算。

### 14. 风险偏好参数尚未针对拉面校准

历史 C++ 使用完整终局分布的排名加权值，并让激进度随剩余回合变化。当前 Rust 已实现 weighted mean/radical factor，但拉面没有针对：

- 平均分模式；
- 凹高分模式；
- PT 模式；
- RMJ 失败风险

做独立校准。

### 15. 没有拉面截断 leaf evaluator

`RamenGame::SUPPORTS_TRUNCATED_LEAF=false`，只能 rollout 到终局。实时搜索成本很高，无法使用浅层搜索 + leaf 估值。需要拉面专属 value evaluator，不能复用温泉 1121 维模型。

## P2：神经网络与数据闭环缺口

### 16. NN 特征、动作空间和 collector 都是温泉专属

当前：

- `extract_nn_features` 只在 `OnsenGame`；
- `NeuralNetEvaluator` 只实现 `Evaluator<OnsenGame>`；
- `action_to_global_index` 只映射 `OnsenAction`；
- `SampleCollector` 只记录温泉动作；
- `collector` 和 standalone `neuralnet` 主入口仍是 `unimplemented!()` 或注释状态。

拉面需要自己的特征和多阶段动作标签：地区、隐藏风味方案、训练、地区选择、超级拉面、事件。

### 17. 缺少搜索蒸馏闭环

历史 AI 的核心路线是：强搜索生成 policy/value 标签，NN 加速后续搜索。当前拉面没有：

1. MCTS 标签采集；
2. 训练数据 manifest/分片；
3. 拉面模型训练与 ONNX 导出；
4. policy/value 离线验证；
5. NN leaf 与全深 rollout A/B；
6. 模型版本和规则版本兼容检查。

### 18. value target 设计不足

旧 collector 使用最终分数 one-hot 动作和固定标准差 500。历史搜索会输出：

- score mean；
- score stdev；
- 风险加权 value；
- 每个动作的访问量/搜索分布。

拉面训练应蒸馏搜索分布，而不是只学最终选中动作；value 也应学习真实 rollout 分布，而不是固定方差。

## P2：验证与工程缺口

### 19. 当前结论只覆盖单马娘、单卡组、单继承配置

`cook2-40` 的 150 seed 优势可信，但泛化尚未验证。至少需要：

- 多马娘（含自选比赛要求不同者）；
- 多卡组构成（速耐、速智、无智卡、多类型卡组）；
- 多继承配置；
- PT 权重/查定模式；
- 500–2000 seed 扩样确认。

### 20. 缺少剧本 KPI 分解

当前报告主要看终局评分/PT/属性。还应统计：

- 每年吃面次数；
- RMJ 成功率与第三年大成功率；
- 年末废弃诀窍；
- 隐藏风味使用量；
- 各地区选择率；
- 吃面后实际训练与窗口目标一致率；
- 失败次数/大失败次数；
- 休息、外出、比赛次数；
- 属性溢出量。

没有这些指标时，只能知道“涨了”，难以知道策略是否以健康方式涨分。

### 21. 实验代码与正式代码分离过度

最佳逻辑由 patch script、workflow 和矩阵 token 逐层构造。问题包括：

- 正常用户无法从配置启用；
- 搜索 rollout 无法复用；
- 默认值不代表推荐值；
- 历史实验字段大量残留；
- 容易出现报告策略与生产策略不一致。

应把已确认配置提升为正式命名 preset，并把失败实验移到 benchmark-only 配置。

### 22. 缺少策略回归语料库

历史复杂手写逻辑依赖大量边界特判。拉面需要保存代表性局面：

- 多彩高人头窗口；
- 诀窍即将溢出；
- RMJ 临界；
- 年末清仓；
- 多个隐藏风味方案；
- 高失败率安全过渡；
- 第三年 5000 临界；
- 超级拉面选择。

每个局面记录期望动作和 breakdown，避免后续调参只看均值却破坏关键行为。

## 推荐实施顺序

### 第一阶段：让当前最佳真实可用

1. 把 `cook2-40 + window10 + rawfail` 固化为命名 preset。
2. `umasim handwritten` 默认拉面路径使用该 preset。
3. `FlatSearch<RamenGame>` rollout 改用同一个 preset。
4. 为 `SuperRamenSelect`、隐藏风味 tie-break、年末清仓补专门策略。
5. 扩展 benchmark KPI 与多卡组矩阵。

### 第二阶段：接通拉面蒙特卡洛

1. 新建 `RamenMctsTrainer`，避免污染温泉专属 `MctsTrainer`。
2. 各拉面阶段接入 `FlatSearch<RamenGame>`；先保留地区/超级拉面手写，再逐步开放搜索。
3. 跑低预算配对实验，测 MCTS 相对最佳手写的真实增益。
4. 测拉面 CRN 等效倍率，校准 `search_n`、UCB group 和 radical factor。
5. 增加每回合估值差与动作分歧日志，但不先验照搬温泉 `+70`。

### 第三阶段：长期上限

1. 设计拉面专属特征与分阶段动作头。
2. 用搜索访问分布生成训练标签。
3. 训练拉面 value/variance/policy 模型。
4. 接入浅层 MCTS + NN leaf，解决实时性能。
5. 接通 `crates/umaai` 的拉面协议与实时推荐。

## 结论

当前最主要的问题已不是“再调一个手写权重”，而是三条链尚未闭合：

1. **最佳实验策略没有进入正式默认和 rollout**；
2. **拉面搜索内核没有正式训练员和实时入口**；
3. **拉面没有 NN/collector/蒸馏闭环**。

短期最高性价比是先修 P0 接线，再做拉面 MCTS 配对实测。继续只在矩阵里增加启发式，收益会越来越小，而且无法转化为用户实际使用的 AI。
